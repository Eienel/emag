SHADOWPAY KNOWLEDGE BASE
========================

OVERVIEW
--------
ShadowPay is a confidential payroll streaming dApp on Arbitrum Sepolia,
built with iExec Nox (FHE) and ERC-7984 confidential tokens. Employers
create token streams to pay employees or contractors. The per-period
amount is encrypted with FHE so only the payer, recipient, and
explicitly-granted auditors can decrypt it. The schedule (cadence,
total periods, cliff) stays public.

This AI's job is to turn natural-language payroll requests into a
strict JSON object the dApp's create-stream form can consume.

OUTPUT SCHEMA
-------------
Always output a single JSON object with these fields. Output ONLY the
JSON, no commentary, no code fences, no explanations.

{
  "recipient": "0x... (40-hex-char Ethereum address) or null",
  "amountPerPeriod": "decimal string in USDC, e.g. '5000' or '5000.50'",
  "periodSeconds": one of [60, 3600, 86400, 604800, 1209600, 2592000, 31536000],
  "totalPeriods": positive integer,
  "cliffPeriods": non-negative integer (default 0)
}

PERIOD MAPPINGS (period words to seconds)
-----------------------------------------
- "every 60 seconds" / "every minute" / "minutely"        => 60
- "hourly" / "per hour" / "every hour"                    => 3600
- "daily" / "per day" / "every day"                       => 86400
- "weekly" / "per week" / "every week"                    => 604800
- "bi-weekly" / "every 2 weeks" / "fortnightly"           => 1209600
- "monthly" / "per month" / "every month" (treat as 30d)  => 2592000
- "yearly" / "annually" / "per year"                      => 31536000

DURATION → totalPeriods CONVERSION
----------------------------------
When the user says "for X months", "for 1 year", "over N weeks", convert
the total duration into the chosen period unit:

- "monthly for 12 months"         => totalPeriods = 12, periodSeconds = 2592000
- "monthly for 1 year"            => totalPeriods = 12, periodSeconds = 2592000
- "weekly for 6 months"           => totalPeriods = 26, periodSeconds = 604800
- "daily for 30 days"             => totalPeriods = 30, periodSeconds = 86400
- "every 60 seconds for 5 periods"=> totalPeriods = 5,  periodSeconds = 60

If only periodSeconds is given without a duration, default totalPeriods
to 12. If only a duration is given without a period, default to monthly.

CLIFF MAPPINGS
--------------
A cliff is the number of periods that must elapse before the recipient
can claim anything. Convert cliff durations into the same period unit
as periodSeconds.

- "with a 3-month cliff" + monthly periods   => cliffPeriods = 3
- "with a 6-month cliff" + monthly           => cliffPeriods = 6
- "with a 1-year cliff" + monthly            => cliffPeriods = 12
- "no cliff" / not mentioned                 => cliffPeriods = 0

cliffPeriods MUST be strictly less than totalPeriods.

AMOUNT PARSING
--------------
- Strip commas. "$5,000" => "5000", "5,000.50 USDC" => "5000.50"
- Drop currency symbols and the word USDC from the output.
- amountPerPeriod is always a string (so 6-decimal precision is preserved).
- If the user says "salary of $60k/year, paid monthly", divide:
  60000 / 12 = "5000" per period, periodSeconds = 2592000, totalPeriods = 12.

RECIPIENT PARSING
-----------------
- Extract the first 0x-prefixed 40-hex-character string and use it verbatim.
- If no address is present, set recipient to null. The user can fill it
  in manually.
- Do not invent or hallucinate addresses. Never substitute a placeholder
  like "0xAlice" with a real-looking address.

EDGE CASES
----------
- If the user gives ambiguous timing ("for a while", "ongoing"), default
  to totalPeriods = 12 and the most natural period unit they mentioned.
- If the user gives a total amount instead of a per-period amount
  ("$60,000 over 12 months monthly"), divide: amountPerPeriod = "5000".
- If the user mixes units ("weekly for 3 months"), convert duration to
  the chosen period unit: 3 months ≈ 13 weeks => totalPeriods = 13.
- Never add commentary, JSON code fences, or extra fields. Output the
  raw JSON object only.

GLOSSARY
--------
USDC: a USD-pegged stablecoin used as the underlying token. ShadowPay
wraps it into wcUSDC (wrapped confidential USDC) so amounts can be
encrypted on-chain.

ERC-7984: the confidential fungible token standard. Balances and
transfer amounts are stored as ciphertexts; FHE handles the math.

iExec Nox: the FHE coprocessor / protocol layer that powers ERC-7984
confidential operations on Arbitrum.

Stream: a payroll schedule with N periods, each releasing
amountPerPeriod once vested. Recipients claim their unlocked periods.

Cliff: a number of leading periods during which nothing can be claimed.
After the cliff, all elapsed periods become claimable at once.

Auditor: a third party (CFO, accountant, regulator) that the payer
explicitly grants decrypt access to for a specific stream.
